# 23 VM: EC2, SSM, EBS, and Process Management

Until now you have not owned a single server. Lambda runs only when it is called, and AWS looks after the operating system. In this chapter you do the opposite and own the machine, operating system included.

You will build one EC2 instance, which is one virtual machine. No SSH port is opened. The notes API from [chapter 04](/en/chapters/04-http-api.md) runs on it as a systemd service, and the notes are kept on a disk separate from the instance.

What this chapter creates is **billed by the hour just for existing**. The default layout costs about USD 2.33 a day and USD 70.74 if you leave it for a month (730 hours), and it still costs USD 62.86 with the instance stopped. The cheaper layout is USD 0.43 a day and USD 13.07 a month. The breakdown is under "What it costs just to exist" on this page. Once you have tried the chapter, go on to the [cleanup](/en/chapters/23-ec2/wrap.md) the same day.

You need the VPC from [chapter 11](/en/chapters/11-network.md). The code is in `examples/23-ec2/`.

## When EC2 is the right place

<!-- section: 23.why -->

If the Lambda function from chapter 04 is enough, you do not need EC2. Lambda costs nothing while unused and AWS patches it, so it is hard to find a place that asks less of you.

You start wanting a machine of your own in cases like these.

- **A process has to run for a long time.** One Lambda invocation lasts 15 minutes at most, so it does not suit holding connections for hours or keeping a large index in memory
- **You need to change the operating system or the kernel.** That covers kernel parameters, file systems, and detailed network settings. Neither Lambda nor Fargate gives you a kernel you can touch
- **You need special hardware.** GPUs, a lot of memory, or fast disks attached directly to the instance
- **You want to run software that no managed service offers.** A database or daemon that you operate yourself is the usual case. celld in chapter 24 is one

In exchange, you take over work that AWS has been doing.

- Patching the operating system and the runtime
- Noticing that the process died, and starting it again
- Watching that the disk does not fill up, and restoring it when it breaks
- Deciding what starts, and in what order, when the machine boots
- Accepting that when this one machine stops, everything stops

This chapter takes these five in turn. The last one has no fix, so the section [One machine is a single point of failure](/en/chapters/23-ec2/wrap.md) states the conditions under which running one machine is acceptable.

## What it costs just to exist

<!-- section: 23.cost -->

Amounts are in USD at on-demand list prices for the Tokyo Region, before tax, with a month counted as 730 hours. The arithmetic is in [Pricing Worksheets](/en/reference/pricing.md).

| Layout | Running, one day | Running, one month | Stopped, one day | Stopped, one month |
| --- | --- | --- | --- | --- |
| Default (private subnet) | 2.33 | 70.74 | 2.07 | 62.86 |
| `-c placement=public` | 0.43 | 13.07 | 0.05 | 1.54 |

The amounts are made up of these items.

- The instance: a `t4g.micro` (2 vCPU, 1 GiB) is USD 0.0108 an hour, which is 7.88 for 730 hours
- The volumes: gp3 is USD 0.096 per GB-month. The 8 GiB root volume and the 8 GiB data volume come to 1.54 together. The AMI decides the size of the root volume, and 8 GiB is an assumption that was not checked on a real instance
- A public IPv4 address (only with `placement=public`): USD 0.005 an hour, which is 3.65 for 730 hours
- Interface endpoints (only in the default layout): USD 0.014 an hour for each endpoint in each zone. Three endpoints in two zones come to 61.32 for 730 hours

The first thing to take from the table is that the volumes are billed while the instance is stopped. Stopping an instance ends the instance charge and nothing else. The disks are still there with their contents, and you keep paying for the space they occupy. Stopping the instance when you are not using it does not bring the cost to zero.

In the default layout, the endpoints account for most of the cost. They are also resources of the chapter 11 stack, so their charge continues whether you stop this chapter's instance or delete it. The reason they are the default anyway is in the section [No SSH port](/en/chapters/23-ec2/build.md).

What a public IPv4 address costs depends on which kind it is. `placement=public` in this chapter uses an address that is assigned automatically at each start. When the instance stops, the address is released and its charge ends, and the next start brings a different address. An Elastic IP address, which you would use to keep the address fixed, is billed while the instance is stopped as well. This chapter does not use an Elastic IP address.

One more charge does not appear in the table. T-family instances such as `t4g` normally use little CPU and spend saved-up CPU credits to run at full speed for a while. Unless you say otherwise, they launch in a mode called unlimited, in which they keep running at full speed after the credits are gone and the excess is billed at USD 0.04 per vCPU-hour. A runaway process then becomes a bill. This chapter's stack sets the mode to standard, so when the credits run out the instance slows down and the bill does not grow.

The table leaves out data transfer, snapshots (USD 0.05 per GB-month), and the S3 bucket that holds releases. They are not included, which is different from being zero. Session Manager and Run Command have no additional charge when used on EC2 instances. The EC2 and EBS documentation mentions Free Tier allowances, but whether they apply to your account could not be confirmed, so nothing is deducted.

There are four figures. From the top, they show who connects to whom, which path that traffic takes, which settings the instance carries, and which volume each file is on.

In the first figure, no arrow enters the instance from outside. You connect to Systems Manager, and the instance opens its own connection to Systems Manager as well. The notes API listens only on `127.0.0.1` inside the instance.
