# 23 VM: EC2, SSM, EBS, and Process Management

So far you have not owned a single server. Lambda runs only when it is called, and AWS looks after the operating system. This chapter goes the other way: you own the machine, operating system and all.

You will build one EC2 instance, which is one virtual machine. No SSH port is opened. The notes API from [chapter 04](/en/chapters/04-http-api.md) runs on it as a systemd service, and the notes live on a disk separate from the instance.

Money first. This chapter creates things that are **billed by the hour just for existing**. The default layout costs about USD 2.33 a day and USD 70.74 if you leave it for a month (730 hours). Stop the instance and it still costs USD 62.86. The cheaper layout is USD 0.43 a day and USD 13.07 a month. The breakdown comes right below. Once you have tried it, please go all the way to the cleanup section the same day.

You need the VPC from [chapter 11](/en/chapters/11-network.md). The code is in `examples/23-ec2/`.

## Why EC2, at this point?

<!-- section: 23.why -->

If the Lambda function from chapter 04 is enough, you do not need EC2. It costs nothing while unused and AWS patches it for you. It is hard to find an easier place to put code.

You start wanting a machine of your own in cases like these.

- **A process has to run for a long time.** One Lambda invocation lasts 15 minutes at most. Holding connections for hours, or keeping a large index in memory, is not what it is for
- **You need to touch the operating system or the kernel.** Kernel parameters, file systems, fine network settings. Neither Lambda nor Fargate gives you a kernel you can change
- **You need special hardware.** GPUs, a lot of memory, fast disks attached directly to the instance
- **You want to run software that no managed service offers.** A database or daemon you operate yourself. celld in chapter 24 is exactly that

In exchange, work that AWS has been doing becomes yours.

- Patching the operating system and the runtime
- Restarting the process when it dies, and noticing that it died
- The disk: whether it fills up, and how to get it back when it breaks
- What starts, and in what order, when the machine boots
- And the fact that when this one machine stops, everything stops

This chapter deals with these five, one at a time. The last one cannot be dealt with. The section on a single point of failure states the conditions for accepting it.

## What it costs just to exist

<!-- section: 23.cost -->

Amounts are in USD, for the Tokyo Region, at on-demand list prices, before tax, with a month of 730 hours. The arithmetic is in [Pricing Worksheets](/en/reference/pricing.md).

| Layout | Running, one day | Running, one month | Stopped, one day | Stopped, one month |
| --- | --- | --- | --- | --- |
| Default (private subnet) | 2.33 | 70.74 | 2.07 | 62.86 |
| `-c placement=public` | 0.43 | 13.07 | 0.05 | 1.54 |

Here is what is inside.

- **The instance**: a `t4g.micro` (2 vCPU, 1 GiB) is USD 0.0108 an hour, 7.88 for 730 hours
- **The volumes**: gp3 is USD 0.096 per GB-month. An 8 GiB root volume and an 8 GiB data volume come to 1.54. The AMI decides the size of the root volume, and 8 GiB is an assumption that was not checked on a real instance
- **A public IPv4 address** (only with `placement=public`): USD 0.005 an hour, 3.65 for 730 hours
- **Interface endpoints** (only in the default layout): USD 0.014 an hour each, per zone. Three of them in two zones come to 61.32 for 730 hours

Three things to take from the table.

**Stopping does not stop the volume charges.** When you stop an instance, only the instance charge stops. The disks are still there with their contents, and you keep paying for the space. "Stop it when idle and it costs nothing" is not true.

**Most of the default layout's cost is the endpoints.** And the endpoints belong to the chapter 11 stack, so stopping or deleting this chapter's instance does not stop them. Why they are the default anyway is explained under "No SSH port".

**With public IPv4 addresses, the kind matters.** `placement=public` in this chapter uses an address that is assigned automatically at each start. It is released when the instance stops, and the charge stops with it. The next start brings a different address. If you want a fixed one and use an Elastic IP address, that one is billed while the instance is stopped too. This chapter uses no Elastic IP address.

There is one more trap that the table does not show. T-family instances such as `t4g` normally use little CPU and spend saved-up CPU credits to run flat out for a while. Left alone, they launch in a mode called unlimited: they may keep running flat out after the credits are gone, and the excess is billed at USD 0.04 per vCPU-hour. A runaway process turns straight into a bill. This chapter's stack sets standard mode. When the credits run out the instance gets slow, and the bill does not grow.

Some things are not in the table: data transfer, snapshots (USD 0.05 per GB-month), and the S3 bucket that holds releases. That means not included, not zero. Session Manager and Run Command have no additional charge when used on EC2 instances. The EC2 and EBS documentation mentions Free Tier allowances, but whether they apply to your account could not be confirmed, so nothing is deducted.

## The big picture

```figure

actor inst: EC2 instance | VPC AihNetwork
actor s3: S3 bucket | releases
step inst -> ssm: HTTPS 443 (SSM Agent)
```

```figure
caption: The instance reaches Systems Manager and S3 through VPC endpoints when private, and through the internet gateway when public
node inst: EC2 instance | VPC AihNetwork (chapter 11), zone ap-northeast-1a
node vpce: VPC endpoints (chapter 11 stack) | ssm, ssmmessages, ec2messages, S3 gateway
node igw: Internet gateway | the instance's public IPv4 address
node ssm: Systems Manager
node s3: S3 bucket | releases

edge inst -> igw: Public1 (-c placement=public)
edge vpce -> ssm
edge vpce -> s3

edge igw -> s3
```

```figure
caption: The instance carries a security group with no inbound rule, a role limited to two permissions, and the IMDSv2 setting
node inst: EC2 instance AihEc2/instance | t4g.micro, Amazon Linux 2023 arm64
node sg: Security group | inbound none, outbound tcp 443
node role: Instance profile role
node imds: IMDSv2 | required, hop limit 1
node core: AmazonSSMManagedInstanceCore
node get: s3:GetObject | releases/*
edge inst -> sg
edge inst -> role
edge inst -> imds

```

```figure
caption: The program and the service live on the root volume, which is deleted with the instance, and the notes live on the data volume, which is its own resource
node inst: EC2 instance AihEc2/instance
node root: Root volume | from the AMI, deleted with the instance
node data: Data volume AihEc2/data | 8 GiB gp3, encrypted, same zone
node current: /opt/notes/current | releases/<version>/server.mjs
node service: notes.service | systemd, user notes, 127.0.0.1:8787
node notes: /var/lib/notes/notes.json
edge inst -> root
edge inst -> data
edge root -> current
edge root -> service
edge data -> notes
```

Did you notice that no arrow enters the instance from outside? You talk to Systems Manager, and the instance goes and talks to Systems Manager itself. The notes API, too, listens only on `127.0.0.1` inside the instance.
