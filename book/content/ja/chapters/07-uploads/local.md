# 07 File Upload: 手元で動かす

[しくみと実装](/ja/chapters/07-uploads/build.md)までで見た添付の機能を、このページでは S3 を使わずに手元で動かします。

## 手元で動かす

<!-- section: 07.local -->

`examples/07-uploads/.env.example` を、同じ場所に `.env` という名前でコピーします。

<<< @/examples/07-uploads/.env.example

ターミナルを 2 つ使い、それぞれで次のタスクを実行します。

```bash
vp run dev:uploads:api
vp run dev:uploads:web
```

<http://localhost:5173> を開いてサインインし、ノートを作って開きます。「Images」の下でファイルを選ぶと、画像が付きます。別のブラウザで `bob` としてサインインしても、Alice のノートも画像も見えません。

Docker も、AWS の認証情報も、バケットも要りません。

### S3 の代わり

アプリは、バイト列を置く場所を、このインターフェースとして受け取ります。AWS の上では S3 が、手元ではメモリ上の実装が使われます。

<<< @/examples/07-uploads/api/src/local-store-http.ts{local-store}

<<< @/examples/07-uploads/api/src/dev.ts{dev}

手元の実装は、フォームを受け取るエンドポイントを開発サーバーの中に持っています。許可証には、開発用の秘密の値で署名した小さなポリシーを入れてあり、違うキー、違う種類、大きすぎるファイル、期限切れを拒否します。

開発サーバーは、パスが `/local/` で始まるリクエストを API に渡しません。`POST /local/token` は 06章の開発用サインインで、それ以外はバケットの代わりが受け取ります。

<<< @/examples/07-uploads/api/src/local-store-http.ts{read-form}

フォームには画像が入っているので、読む量に上限を付けます。04章の `readJson` は JSON しか読まないので、同じ数え方をする関数をこの章に書きました。上限は 5 MiB より 64 KiB だけ大きくしてあります。少し大きいだけのファイルは最後まで読んで、ポリシーの大きさの条件で 400 を返します。上限を超えた分は読まずに 413 を返します。どちらも手元の実装の振る舞いで、S3 が返すものではありません。

手元の実装は S3 の模擬ではなく、アプリの順序と認可を動かすための代わりです。次のものは再現しません。

- POST ポリシーの実際の評価。S3 が何を、どんなレスポンスで拒否するかは再現しません
- バケットの CORS。手元では、開発サーバーが自分で CORS のヘッダーを返します
- IAM。実行ロールの権限が足りているかどうかはわかりません
- ライフサイクルルール。手元では、pending のオブジェクトがいつまでも残ります
- 認証情報の失効によって URL が早く切れること

S3 互換のサーバーをコンテナで動かせば、もう少し本物に近づけられます。そのためには Docker が要りますが、Docker のデーモンは Nix の shell に含まれません。この章は、そのためのタスクを用意していません。執筆した環境ではデーモンが動いていなかったので、試してもいません。

### 画面

SPA は、06章の `web/` を土台にしています。サインイン、設定の読み込み、ルートの解釈は、06章のファイルをそのまま import しています。足したのは、ノートの編集画面の下に出る画像の欄だけです。

<<< @/examples/07-uploads/web/src/check-file.ts{check-file}

ファイルを選んだときに、種類と大きさをブラウザの側でも確かめます。この確認は利用者に早く知らせるためのもので、守りではありません。確認を通らないファイルを直接送っても、S3 が拒否します（手元では、メモリ上の実装が拒否します）。
