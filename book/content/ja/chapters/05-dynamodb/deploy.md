# 05 KV Store: デプロイ

手元で動いた API を AWS にのせます。04章の構成から増えるのは、DynamoDB のテーブルと、関数がそのテーブルを使うための権限と設定です。

## AWS にのせる準備

`billingMode` はオンデマンドです。オンデマンドでは読み書きの回数に対して料金がかかり、容量を前もって決めなくて済みます。もう 1 つの選択肢はプロビジョンド（provisioned）で、1 秒あたりの読み書きの容量を決め、確保した時間のぶんを払います。リクエストの量が安定していて予測できるなら、プロビジョンドのほうが安くなることがありますが、使わない時間にも料金がかかります。学習用や、リクエストの量が読めない新しいアプリには、オンデマンドが向いています。

`maxReadRequestUnits` と `maxWriteRequestUnits` は、テーブルが 1 秒に受ける読み書きの上限です。オンデマンドは使ったぶんだけ払う方式なので、上限を書かなければ、大量に呼ばれたぶんがそのまま請求になります。上限を超えたぶんは、DynamoDB が断ります。

<<< @/examples/05-dynamodb/infra/lib/notes-stack.ts{limits}

入口の API Gateway にも、04章と同じ 1 秒に 10 件のスロットリングを付けました。テーブルの上限は、この API が 1 回のリクエストで使いうる最大より上にしてあります。一覧は 1 回で最大 20 件を読み、いちばん大きなノート（本文 10,000 文字）ばかりなら 610 KB ほどなので 77 ユニット、そのノートを 1 件書くと 31 ユニットほどです。上限をそれより小さくしたときに、大きなノートが 1 件も通らなくなるのかどうかを確かめていないので、上にしてあります。

`removalPolicy` は `DESTROY` です。練習用なので、スタックを消すと、テーブルもその中のノートもすべて消えます。守るべきデータを入れるようになったら最初に変える設定なので、テストはこの値を明示的に確かめています。

<<< @/examples/05-dynamodb/infra/lib/notes-stack.ts{role}

`table.grantReadWriteData(role)` と書けば 1 行で済みますが、その権限には、テーブル全体を読む `Scan` や、まとめて読み書きする操作も入っています。このアプリはどれも使いません。使わない権限は、コードに欠陥があったときに悪用できる範囲を広げるだけなので、使う 5 つの操作だけを並べています。テストは、操作がこの 5 つであることと、対象がこのテーブルの ARN だけであることを確かめています。

<<< @/examples/05-dynamodb/infra/lib/notes-stack.ts{function}

`TABLE_NAME` は、デプロイのときに決まるテーブルの名前を、環境変数で関数に渡します。コードにはテーブルの名前を書きません。

`externalModules: []` は、AWS SDK をバンドルに含める指定です。何も指定しないと、SDK はバンドルから外され、Lambda のランタイムに入っている版が使われます。その版は、このリポジトリのロックファイルとは無関係です。バンドルに含めておけば、テストしたのと同じ版が動きます。そのぶんバンドルは大きくなります。

`banner` の 1 行は、SDK をバンドルに含めたことの副作用に対処しています。バンドルに入った SDK は内部で `require()` を呼びますが、ES module には `require` がないので、そのままでは関数が読み込まれた時点で落ちます。そこで、バンドルの先頭で `require` を用意しています。テストの実行環境は `require` を持っているので、ユニットテストはこの問題を見つけられません。そのため `vp run bundles:check` が、synth したバンドルを素の Node.js で読み込んで確かめます。

## デプロイして確かめる

<!-- section: 05.deploy -->

```bash
vp run notes:infra:diff
vp run notes:infra:deploy
vp run notes:smoke
```

`notes:smoke` は、型付きのクライアントでノートを 1 件作り、読み戻し、更新し、わざと古い `version` で更新して拒否されることを確かめ、最後に消します。04章の `api:smoke` と違って、読み戻しはどの実行環境が答えても成功しなければなりません。

テーブルの中身は、コンソールの DynamoDB の画面で「項目を探索」から見られます。

ドリフトの検査は、これまでの章と同じです。

```bash
vp run notes:infra:drift
```

`AWS::DynamoDB::Table` は、固定した版の cdkd が専用の実装で扱う種類です。実際の AWS での結果は、まだ確かめていません。
