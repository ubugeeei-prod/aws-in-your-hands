# 02 Toolchain: デプロイ

bootstrap まで済んだところから続けます。このページでは、サンプルのスタックを AWS にデプロイし、diff とドリフトがそれぞれ何を比べているのかを確かめます。

## デプロイする

<!-- section: 02.deploy -->

```bash
vp run hello:infra:diff
vp run hello:infra:deploy
```

`diff` は、これから作られるものを表示します。初回は、バケットとバケットポリシーの 2 つが「作成」として表示されるはずです。実際に作るのは `deploy` です。どちらのタスクも、実行の前にアカウントとリージョンを表示し、`AIH_AWS_ACCOUNT_ID` と一致しなければ止まります。

デプロイが終わると、バケットの名前が出力されます。コンソールの S3 の画面でも確かめられます。

設定を変えてもう一度 diff を取ると、変更した部分だけが表示されます。

```bash
vp run hello:infra:diff -c noncurrentVersionDays=30
```

## diff とドリフトは別のもの

<!-- section: 02.diff-drift -->

ここまでに、バケットの設定を表すものが 4 つ出てきました。

| | 何か | どこにあるか |
| --- | --- | --- |
| ソース | CDK のコード | リポジトリ |
| テンプレート | synth の出力 | `cdk.out/` |
| state | cdkd が「こう作った」と記録したもの | `cdkd-state-...` バケット |
| 実物 | いま AWS にある設定 | AWS |

diff は、テンプレートと state を比べて、このコードをデプロイしたら何が変わるかを予告します。実物は見ません。

ドリフトの検出は、state と実物を比べて、記録どおりの設定がいまも AWS にあるかを確かめます。誰かがコンソールで設定を変えると、ここに差が出ます。

したがって、**diff が空でも、ドリフトが無いとは言えません**。コンソールでバケットのバージョニングを止めても、コードも state も変わらないので、diff は「変更なし」と表示します。

CloudFormation の経路にも同じ区別があります。`cdk diff` はテンプレートどうしの比較で、実物との比較は CloudFormation の drift detection という別の機能です。drift detection は [20章](/ja/chapters/20-shipping.md)で扱います。

## ドリフトを見つける

<!-- section: 02.drift-gate -->

```bash
vp run hello:infra:drift
```

このタスクは `cdkd drift AihHello --json` を実行し、結果を `reports/drift/AihHello.json` に書いて、最後に合否を出します。AWS を読みますが、変更はしません。

合否の判定を、cdkd の終了コードだけには任せていません。固定した版の cdkd は、次の場合にも終了コード 0 を返すからです。

- 読み戻す手段がない種類のリソースがあり、比較していない
- 比較を省いたリソースがある

差が見つからなかったことと、すべてを比べて一致したことは、同じではありません。この本の判定（コードでは gate と呼んでいます）は、すべてのリソースを比べて一致したときだけ合格にします。

<<< @/tools/src/drift/report.ts{gate}

状態は 7 つあります。

| 状態 | 意味 | 判定の終了コード |
| --- | --- | --- |
| `clean` | すべて比べて一致した | 0 |
| `drifted` | 記録と違う設定がある | 10 |
| `deleted` | 記録にあるリソースが AWS に無い | 10 |
| `incomplete` | 読み出しに失敗するなどして、比べられなかったものがある | 11 |
| `unsupported` | 読み戻せない種類のリソースがあり、比べていない | 11 |
| `failed` | 検出そのものが結果を出さなかった | 12 |
| `missing-target` | 指定したスタックの記録が無い | 12 |

終了コードを分けたのは、違いがある場合とわからない場合を、CI が区別できるようにするためです。レポートには、実行した時刻、アカウント、リージョン、比べた数と比べなかった数が残ります。

cdkd の出力も、この本のコードから見れば外から来るデータなので、スキーマで検証してから読みます。出力が空だった、指定したスタックが含まれていなかった、終了コードと中身が食い違っていた、といった場合は、都合のよいほうに解釈せず、`failed` か `missing-target` にします。この扱いは、`tools/src/drift/fixtures/` にある 9 つの入力に対してテストしています。ただし、これらの入力は cdkd の型定義をもとに手で書いたもので、実際の AWS から採取した出力ではありません。

### ドリフトが見つかったら

選択肢は 3 つあり、どれを選ぶかは人が決めます。

- 実物を記録に戻す。`vp run hello:infra:drift:revert:preview` で内容を確かめてから、`vp run hello:infra:drift:revert` を実行します。置き換えが必要な変更では、データを持つリソースが作り直される場合があるので、preview の出力は必ず読んでください
- 実物の設定を正とする。`vp run hello:infra:drift:accept` を実行します。書き換わるのは state だけで、CDK のコードは変わらないので、そのままでは次のデプロイで元に戻ります。コードも同じ値に直してください
- コードを直してデプロイし直す。コードを変更して `vp run hello:infra:deploy` を実行します。意図した変更なら、これが本来の手順です

どれを選んでも、最後にもう一度 `vp run hello:infra:drift` を実行します。解消のコマンドが成功したことは、スタックが一致していることの証明にはなりません。

### 試してみる

デプロイしたバケットで、次の順に試せます。

1. コンソールでバケットの「バージョニング」を「停止」に変える
2. `vp run hello:infra:diff` を実行する。変更なしと出るはず
3. `vp run hello:infra:drift` を実行する。`drifted` になり、終了コードが 10 になるはず
4. `vp run hello:infra:drift:revert:preview` で戻す内容を見て、`vp run hello:infra:drift:revert` で戻す
5. もう一度 `vp run hello:infra:drift` を実行し、`clean` を確かめる

「はず」と書いたのは、この手順をまだ実際の AWS アカウントで実行していないからです。
