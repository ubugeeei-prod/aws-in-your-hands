# 53 EFS: 手元で動かす

[前のページ](/ja/chapters/53-efs/build.md)で作ったリポジトリは、ディレクトリさえあれば動きます。このページでは、手元のディレクトリを 2 つのプロセスで共有して動かし、テストが何を見ていて何を見ていないかを確かめます。AWS のアカウントは要りません。

## 2 つのプロセスと 1 つのディレクトリ

<!-- section: 53.local -->

開発用のサーバーは、04章の API をディレクトリの上で動かします。

<<< @/examples/53-efs/src/dev.ts{dev}

ターミナルを 2 つ開いて、ポートだけを変えて起動します。`NOTES_DIR` を指定しなければ、どちらも `examples/53-efs/.data` を使います。

```bash
vp run dev:efs
PORT=8788 vp run dev:efs
```

片方に書いて、もう片方から読みます。

```bash
curl -s -X POST http://localhost:8787/notes -H 'content-type: application/json' -d '{"title":"written through 8787"}'
curl -s http://localhost:8788/notes
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8788/notes/..%2F..%2Fetc%2Fpasswd
```

2 行目の一覧に、1 行目で作ったノートが出ます。3 行目は 404 です。ノートは `.data/notes/` に 1 件 1 ファイルでできていて、`.data/incoming/` は空です。23章のリポジトリで同じことをすると、それぞれのプロセスが自分のメモリの内容でファイルを置き換えるので、片方で作ったノートが消えます。前のページのテストが、その様子を再現しています。

テストと synth は次のとおりです。

```bash
vp run test:unit
vp run efs:infra:synth
```

テストが見ているものと、見ていないものを並べます。

| どこ | 見ているもの | 見ていないもの |
| --- | --- | --- |
| `test/note-files.test.ts` | メモリ上の共有ファイルシステムで、書き込みの各段階で書き手が消えたときに読み手に見えるもの。ID の検査、件数の上限、04章の API を 2 つ載せたときの動き | 本物のファイルシステム |
| `test/two-writers.test.ts` | 手元の本物のファイルシステムで、その場での上書き、rename による置き換え、23章のリポジトリを 2 つ開いたときの消失、追記 | NFS。別のマシンどうしの見え方 |
| `infra/test/efs-stack.test.ts` | ポリシー、セキュリティグループ、ロール、マウントの設定、リソースの種類 | AWS がテンプレートどおりに動くこと |

手元のファイルシステムと NFS で、同じことと違うことを分けておきます。この章を書いたマシンは macOS で、ファイルシステムは APFS です。

同じなのは、API と、`rename` が置き換えを 1 回の操作で行うことです。`open`、`write`、`fsync`、`rename`、`readdir`、`unlink` は、マウント先が EFS でも同じ呼び出しです。テストの 2 つの書き手は 1 つのプロセスの中にいますが、カーネルにとっては、2 つのプロセスがそれぞれ開いたファイルと変わりません。

違うのは次の点で、どれも手元では再現していません。

- 手元では、書いた内容はすぐに全員に見えます。NFS では、クライアントごとにキャッシュがあり、別のクライアントの変更が見えるまでに遅れがあり得ます。rename した直後のファイルや、ディレクトリの一覧が、別の実行環境からいつ見えるかは測っていません
- 手元では、追記は 1 回の操作です。NFS では、そうではありません。追記のテストの 2 つ目は、その違いを手元でまねたモデルです
- 手元では、操作は成功するか失敗するかのどちらかです。NFS では、成功したのに応答が届かないことがあります。`test/note-files.test.ts` の、書き手が sync の途中で消えるケースが、これに当たるものをメモリ上で再現しています
- 手元には、スループットの上限も、操作ごとの料金もありません

[次のページ](/ja/chapters/53-efs/wrap.md)に、デプロイして確かめる手順があります。用意してあるだけで、実行した結果ではありません。
