# 51 Chime SDK: 自分のアプリに音声とビデオの通話を入れる

通話の機能でサーバーが決めるのは、誰をその通話に入れるかだけです。音声と映像は、ブラウザーと Amazon Chime SDK のメディアサービスのあいだを直接流れます。この章では、ノートのアプリに「部屋」を足し、部屋に入ってよい人にだけ通話の席を渡す API を作ります。

先に、名前のことを片付けておきます。Amazon Chime という名前の会議アプリは、2026 年 2 月 20 日にサポートが終わりました。この章で使う Amazon Chime SDK は別のサービスで、終了の対象ではありません。経緯は次の節に書きます。

料金は、接続している人数と時間で決まります。東京リージョンでは、アテンディー（参加者）1 人が 1 分接続するごとに USD 0.0017 です（2026-10-13 に AWS Price List で確認）。誰も接続していないあいだは、Chime SDK の料金はかかりません。ただし、タブを開いたまま忘れると、ミーティングが上限の 24 時間で終わるまで課金が続きます。金額と片付けは[費用のページ](/ja/chapters/51-chime-sdk/wrap.md)にあります。

[06章](/ja/chapters/06-auth.md)のサインインと API をそのまま使い、一方向のライブ配信を扱った[18章](/ja/chapters/18-live.md)と比べながら進めます。コードは `examples/51-chime-sdk/` にあります。

## 全体像

<!-- section: 51.overview -->

```figure
caption: API は席を渡すだけで、音声と映像はブラウザーとメディアサービスのあいだを流れる
node browser: ブラウザー | Vue のページ、amazon-chime-sdk-js
node api: API Gateway + Lambda | 06章の JWT オーソライザーの後ろ
node table: DynamoDB | 部屋、メンバー、席
node control: Chime SDK の API | ap-northeast-1、ミーティングとアテンディー
node media: Chime SDK のメディアサービス | メディアリージョン
edge browser -> api: POST /rooms/{id}/join
edge api -> table: メンバーか、席は誰のものか
edge api -> control: CreateMeeting, CreateAttendee
edge api --> browser: 接続先と join token
edge browser -> media: join token を見せて接続
group aws: AWS = api, table, control, media
mark api
```

図の上から順に説明します。サインインした利用者がブラウザーから `POST /rooms/{id}/join` を呼ぶと、API は DynamoDB のテーブルを見て、その利用者が部屋のメンバーかどうかを確かめます。メンバーなら Chime SDK の API でミーティング（meeting）とアテンディー（attendee）を作り、接続先の URL と **join token** をブラウザーに返します。ブラウザーはそれを使ってメディアサービスに接続し、そこから先の音声と映像は API を通りません。

join token は、持っている人がそのアテンディーになれる秘密の文字列です。この章で守ることは、この 1 点に集まります。

> 不変条件: join token は、サインインしていて部屋のメンバーである利用者のためにだけ作られ、その本人にだけ渡る。退出したら、そのトークンは使えなくなる。

図で強調してある API が、この不変条件を守る場所です。Chime SDK は、部屋もメンバーも知りません。誰のアテンディーを作るかを決めるのは、すべてこちらのコードです。

## Amazon Chime と Amazon Chime SDK

<!-- section: 51.status -->

同じ名前が付いていますが、別のものです。

**Amazon Chime** は、会議、通話、チャットのためのアプリとそのサービスでした。AWS は 2025 年 2 月 19 日に終了を告知し、その日から新しい顧客の受け付けを止め、2026 年 2 月 20 日にサポートを終えています。管理者ガイドの告知には、その日以降は Amazon Chime のコンソールにもアプリのリソースにもアクセスできなくなると書かれています。既存のアカウントで「Amazon Chime」という名前の設定や請求の項目を見かけたら、この終わったサービスのものです。新しく使い始めることはできません。

**Amazon Chime SDK** は、自分のアプリに音声、映像、画面共有、メッセージを組み込むための部品です。終了の告知には「Amazon Chime SDK の提供には影響しない」とあり、ドキュメントも、SDK は Amazon Chime の管理者アカウントとは独立に動くと説明しています。この章を書いた 2026-10-13 の時点で、料金表にも API リファレンスにも Chime SDK は載っています。

名前の名残はいくつかあります。IAM のアクションは `chime:CreateMeeting` のように `chime:` で始まり、リソースの ARN にも `chime` が入ります。API には古い名前空間（`Chime`、`us-east-1` だけ）と新しい名前空間（`ChimeSDKMeetings`、複数のリージョン）があり、ドキュメントは新しく始めるなら後者を使うように書いています。この章が使うのは後者だけです。

## ミーティング、アテンディー、join token

<!-- section: 51.model -->

Chime SDK のミーティングで登場するものは 3 つです。

**ミーティング**は、通話 1 つを表す一時的なリソースです。`CreateMeeting` で作り、`DeleteMeeting` で終わらせます。放っておいても、ミーティングの時間が 24 時間を超えるか、誰も接続していない時間が 5 分続くと、Chime が終わらせます。つまり、こちらのテーブルが「この部屋のミーティングは X」と覚えていても、X がまだあるとは限りません。

**アテンディー**は、ミーティングの中の 1 人ぶんの席です。`CreateAttendee` に `ExternalUserId` を渡して作ります。`ExternalUserId` は、アテンディーをこちらのアプリの利用者に結びつけるための値で、この章ではトークンの `sub` を入れます。

**join token** は、アテンディーを作ったときの応答に 1 つ入っています。ブラウザーはこれをメディアサービスに見せて、そのアテンディーとして接続します。API リファレンスによると、join token が使えなくなるのは、ミーティングが終わったときか、`DeleteAttendee` を呼んだときです。時間で切れるとは書かれていません。同じ join token で 2 台目の端末から接続すると、通話は新しい端末に引き継がれ、先の端末は切断されます。

### サーバーがすること、ブラウザーがすること

サーバー側のアプリの仕事は、ミーティングとアテンディーを作り、その 2 つを、権限のあるクライアントに安全に届けることです。使うのは AWS SDK の `@aws-sdk/client-chime-sdk-meetings` で、Chime SDK のクライアントライブラリーは要りません。

ブラウザーの仕事は、受け取った 2 つをクライアントライブラリーに渡し、マイクとカメラを選び、接続することです。ライブラリーは npm の `amazon-chime-sdk-js` で、確認した時点の現行版は 3.32.0（Apache-2.0）でした。ほかに iOS、Android、Windows 向けのライブラリーがあります。

メディアサービスの中では、音声と映像の扱いが違います。音声は、サービスが全員ぶんを混ぜ、聞く人自身の声を除いた 1 本にして送ります。映像は混ぜずに、送られてきたものを必要な相手に転送します（SFU）。1 つのミーティングで同時に送れる映像は 25 本までです。

### リージョンは 2 つ選ぶ

ミーティングには、コントロールリージョンとメディアリージョンがあります。コントロールリージョンは API を呼ぶ先で、メディアリージョンは音声と映像を中継する場所です。1 つのコントロールリージョンから、同じパーティションのどのメディアリージョンにもミーティングを作れます。

東京（`ap-northeast-1`）は両方に対応しています。この章のスタックは、API もメディアも東京に置きます。参加者が別の地域にいるなら、メディアだけを近いリージョンにできます。`https://nearest-media-region.l.chime.aws` をブラウザーから呼ぶと、いちばん近いメディアリージョンが返ります。

ミーティングを更新できるのは、作ったコントロールリージョンからだけです。ミーティングのイベントも、そのリージョンに届きます。

### 上限

2026-10-13 に読んだ時点の既定値です。上限は変わるので、使う前に [Amazon Chime SDK endpoints and quotas](https://docs.aws.amazon.com/general/latest/gr/chime-sdk.html) と Service Quotas のコンソールで確かめてください。

- 1 つのミーティングのアテンディーは 250 人まで（引き上げ不可）
- 同時に開けるミーティングは 250（引き上げ可）
- `CreateMeeting`、`CreateAttendee`、`DeleteAttendee`、`DeleteMeeting`、`GetMeeting` は、それぞれ毎秒 10 リクエスト（引き上げ可）

クォータは API のエンドポイントごと、つまりコントロールリージョンごとに数えられます。毎秒 10 回という値は、通話の開始時刻に利用者が一斉に入ってくるアプリでは、すぐに届きます。この章の API は、ステージ全体を毎秒 10 リクエストで絞っています（[しくみと実装のページ](/ja/chapters/51-chime-sdk/build.md)）。

## IVS、IVS Real-Time、Chime SDK

<!-- section: 51.choice -->

AWS には、映像を届けるサービスが 3 つあります。選ぶ基準は、会話かどうかです。

| | IVS low-latency（18章） | IVS Real-Time | Chime SDK のミーティング |
| --- | --- | --- | --- |
| 形 | 1 人が送り、大勢が見る | 少数が舞台に立ち、大勢が見る | 全員が話す |
| 遅延（公式の表現） | 5 秒未満 | 300 ミリ秒未満になりうる | リアルタイムの音声と映像 |
| 送れる人数の既定値 | 1 チャンネルに 1 本 | 1 ステージに 12 人 | 映像は 25 本、参加は 250 人 |
| 見る人数の既定値 | リージョン全体で同時 15,000 | 1 ステージに 10,000 | 250 人に含まれる |
| 課金の単位 | 入力の時間と視聴の時間 | 参加者ごとの時間 | アテンディーごとの分 |

18章の IVS は一方向の配信です。数秒遅れても困らない代わりに、大勢に届けられます。IVS Real-Time は、いまも提供されている別の製品で、少数の出演者と大勢の視聴者という形のまま、遅延を会話ができる程度まで縮めたものです。Chime SDK のミーティングは、参加者が対等に話す会議や通話のためのもので、人数の上限は小さく、音声はサービスが混ぜて届けます。

単価も比べておきます。Chime SDK は 1 分 USD 0.0017 なので、1 人 1 時間で USD 0.102 です。IVS Real-Time は、日本を含む地域の最初の段階で、参加者 1 人 1 時間あたり USD 0.092 です（どちらも 2026-10-13 に Price List で確認）。近い値なので、選ぶ理由は料金ではなく形になります。全員が話すなら Chime SDK、話す人と見る人が分かれるなら IVS Real-Time、会話にならなくてよいなら IVS です。

### Cloudflare と Vercel

Cloudflare には、近いものがあります（2026-10-13 時点のドキュメントによる）。Cloudflare Realtime は 2 つの製品から成ります。RealtimeKit は、会議の UI と SDK が付いたもので、バックエンドが REST API でミーティングを作り、参加者を足し、参加者ごとの認証トークンをクライアントに渡します。この章の構成と同じ役割分担です。Realtime SFU は、もっと低い層の部品で、シグナリングも権限もアプリが受け持ちます。SFU と TURN の料金は、Cloudflare から出ていくデータ 1 GB あたり USD 0.05 で、毎月 1,000 GB までは無料です。RealtimeKit の料金は別の表にあり、ここでは引用しません。

アプリが Workers の上にあるなら、Cloudflare Realtime を使うほうが動く部品は少なくなります。Chime SDK を選ぶ理由になるのは、利用者の認証やデータがすでに AWS にあること、録画を S3 に置きたいこと、電話網とつなぎたいことです。

Vercel には、WebRTC の音声と映像を中継するサービスが見当たりません。ドキュメントの目次と、リアルタイムのデータを扱うガイドを読んだかぎり、載っているのは WebSocket、SSE、Redis、Queues で、ガイドは必要に応じて外部の事業者を使うように書いています。Vercel の上のアプリに通話を入れるなら、メディアは Chime SDK や Cloudflare Realtime のような外のサービスに任せ、席を渡す API だけを Vercel の関数に書くことになります。

### 使わないほうがよいとき

2 人だけの通話で、相手のネットワークを選ばなくてよいなら、ブラウザーどうしを直接つなぐ WebRTC で足り、メディアを中継するサービスは要りません。会議そのものが目的で、自分のアプリに組み込む必要がないなら、既製の会議サービスを使うほうが早く済みます。数百人を超える聞き手に届けたいなら、Chime SDK の 250 人という上限より、IVS のほうが合います。
