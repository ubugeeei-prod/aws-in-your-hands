# 24 Self-hosting: 手元で動かす

## 手元で確かめられること、確かめられないこと

<!-- section: 24.local -->

AWS に何も作らなくても、次のタスクは手元で実行できます。

```bash
vp run test:unit
vp run celld:plan nodes=3
vp run celld:render
vp run celld:infra:synth -c nodes=3
vp run celld:fetch
```

テストが確かめているのは、次の 4 つです。

- スタックが作るもの。既定では時間課金のリソースが 0 個であること、インバウンドのルールがグループ自身からの 1 行だけであること、IMDSv2 が必須であること、バケットとボリュームが残る設定であること、ロールに `*` が無いこと
- ユニットとインストールのスクリプト。celld の 2 つの要求（再起動の間隔と停止の猶予）を破る設定を作れないこと、ダイジェストの合わないアーカイブを拒むこと。後者は、本物のスクリプトを bash で動かして確かめます
- 更新の順序。[デプロイ](/ja/chapters/24-celld/deploy.md)のページの「fleet にして、1 台ずつ入れ替える」で説明します
- ノードを失ったときの検査の判定。同じページの「ノードを 1 台失う」で説明します

celld そのものは、手元のテストでは確かめられません。celld には `celld dev` という、クラウドのバケットなしでノードを 1 つ動かすコマンドがあります。アプリケーションを書くなら、最初は `celld dev` で動かすのがよさそうです。ただし、この章の執筆ではバイナリを実行していないので、使い勝手については書けません。
