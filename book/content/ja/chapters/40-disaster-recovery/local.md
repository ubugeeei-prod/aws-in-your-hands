# 40 Disaster Recovery: 手元で動かす

## 手元で動かす

<!-- section: 40.local -->

DRS そのものは、手元では動きません。エージェントも、レプリケーションサーバーも、スナップショットも、AWS の中にしかないからです。手元で確かめられるのは、その周りで自分が下す判断です。AWS のアカウントは要りません。

```bash
vp run dr:demo
```

2 つの拠点をメモリの中に作り、failover と failback を 2 回通します。1 回目は、元のサーバーを復旧先の内容で上書きするだけの failback です。2 回目は、元のサーバーを止めてから、そこにしか無い書き込みを数えて記録する failback です。1 回目では、記録に残らないまま消えるノートが 2 件出ます。続けて、復旧の順序が途中で失敗して再実行される様子と、起動はしたがノートを確かめていない訓練の集計が表示されます。

表示される時刻は、説明のために決めた値です。何かを起動して測ったものではありません。

テストと、そのほかのタスクは次のとおりです。

```bash
vp run test:unit
vp run dr:plan kernel=6.1
vp run dr:infra:synth
vp run dr:infra:synth -c placement=public
```

`dr:plan` は、ソースの条件、経路、料金、API で実行する手順を表示します。`dr:infra:synth` は、スタックのテンプレートを `examples/40-disaster-recovery/cdk.out/` に出します。どちらも AWS には問い合わせません。

テストが確かめているのは、次のことです。

- 訓練の計画: 遅れが RPO を超えるサーバー、遅れが報告されないサーバー、最初の同期が終わっていないサーバー、保持より古い時刻の指定
- 訓練の合否: 確認が 1 つ欠けていれば未完了、1 つ失敗していれば不合格
- 復旧の順序: 途中の失敗、再実行、応答だけが失われた場合
- 2 つの拠点: 複製の遅れ、split brain、failback の後に黙って消えた書き込みが無いこと
- イベント: ドキュメントのサンプルの形、知らない状態の拒否
- 「まだ課金されているもの」の一覧: 訓練のインスタンスと本当の復旧のインスタンスの区別
- スタック: エージェントの権限、エンドポイントの置き場所、既定では DRS のリソースを宣言しないこと

手元では再現しないものを、はっきりさせておきます。複製にかかる時間、遅れの実際の値、起動にかかる時間、変換の成否、エージェントが 23章のインスタンスで動くかどうかは、どれも AWS の上でしかわかりません。テストが通ることは、判断のコードが書いたとおりに動く、ということしか示しません。
