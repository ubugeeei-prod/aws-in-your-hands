# 23 VM: EC2、SSM、EBS、プロセス運用

ここまで、サーバーを 1 台も持たずに来ました。Lambda は呼ばれたときだけ動いて、OS のことは AWS が見てくれます。この章では逆に、OS ごと自分で持ちます。

作るのは EC2 の instance、つまり仮想マシンを 1 台です。SSH の port は開けません。[04章](/ja/chapters/04-http-api.md)のノート API を systemd の service として動かして、ノートは instance とは別の disk に置きます。

先にお金の話を。この章は、**置いてあるだけで時間で課金されるもの**を作ります。既定の構成だと 1 日でおよそ USD 2.33、1 か月（730 時間）置きっぱなしで USD 70.74。instance を止めても USD 62.86 かかり続けます。安いほうの構成なら 1 日 USD 0.43、1 か月 USD 13.07 です。内訳はすぐ後で話します。試したら、その日のうちに「片付け」まで進めてくださいね。

前提は [11章](/ja/chapters/11-network.md)の VPC です。コードは `examples/23-ec2/` にあります。

## なぜ今さら EC2？

<!-- section: 23.why -->

04章の Lambda で足りているなら、EC2 は要りません。使っていない間の料金が 0 で、patch も AWS がやってくれる。あれより楽な置き場所は、なかなかありません。

それでも machine を 1 台持ちたくなるのは、こんなときです。

- **プロセスを長く動かしたい。** Lambda の 1 回の実行は最長 15 分です。何時間も接続を持ち続ける、メモリに大きな index を載せたままにする、といった使い方には向きません
- **OS やカーネルを触りたい。** カーネルのパラメーター、ファイルシステム、ネットワークの細かい設定。Lambda にも Fargate にも、あなたが触れるカーネルはありません
- **特殊なハードウェアが要る。** GPU、大きなメモリ、instance に直接つながった高速な disk
- **managed なサービスに無いソフトウェアを動かしたい。** 自分で運用するデータベースや daemon。24章の celld がまさにそれです

引き換えに、いままで AWS がやってくれていたことが、あなたの仕事になります。

- OS と runtime の patch
- プロセスが落ちたら起こすこと、落ちたと気づくこと
- disk。あふれないか、壊れたらどう戻すか
- machine が起動したときに、何がどの順で立ち上がるか
- そして、その 1 台が止まったら全部止まる、という事実

この章は、この 5 つを 1 つずつ片付けていく章です。最後の 1 つだけは片付きません。「1 台は単一障害点」の節で、受け入れる条件を書きます。

## 置いてあるだけでかかるお金

<!-- section: 23.cost -->

金額は USD、東京リージョン、従量課金の定価、税別、1 か月は 730 時間です。計算の中身は[料金の計算](/ja/reference/pricing.md)にあります。

| 構成 | 動かしている 1 日 | 動かしている 1 か月 | 止めている 1 日 | 止めている 1 か月 |
| --- | --- | --- | --- | --- |
| 既定（private subnet） | 2.33 | 70.74 | 2.07 | 62.86 |
| `-c placement=public` | 0.43 | 13.07 | 0.05 | 1.54 |

中身はこうです。

- **instance**: `t4g.micro`（2 vCPU、1 GiB）が 1 時間 USD 0.0108。730 時間で 7.88
- **volume**: gp3 が 1 GB・1 か月あたり USD 0.096。root の 8 GiB と data の 8 GiB で 1.54。root の大きさは AMI が決めるもので、8 GiB は仮定です（実機で確かめていません）
- **public IPv4 アドレス**（`placement=public` のときだけ）: 1 時間 USD 0.005。730 時間で 3.65
- **interface endpoint**（既定の構成のときだけ）: 1 つ・1 AZ あたり 1 時間 USD 0.014。3 つを 2 つの AZ に置いて、730 時間で 61.32

表から読み取ってほしいことが 3 つあります。

**止めても、volume の料金は続きます。** instance を stop すると、止まるのは instance の料金だけです。disk は中身ごと残っているので、置き場所代がかかり続けます。「使わないときは止めておけば 0」にはなりません。

**既定の構成の料金は、ほとんどが endpoint です。** そして endpoint は 11章の stack のリソースなので、この章の instance を止めても消しても、止まりません。なぜそれでも既定にしたのかは、「SSH の port は開けない」で話します。

**public IPv4 アドレスは、種類で話が変わります。** この章の `placement=public` が使うのは、起動のたびに自動で割り当てられるアドレスです。instance を止めると手放されて、課金も止まります。次に起動すると別のアドレスになります。固定したくて Elastic IP アドレスを使うと、そちらは止めている間も課金されます。この章は Elastic IP アドレスを使っていません。

もう 1 つ、表に出てこない落とし穴があります。`t4g` のような T 系の instance は、普段は CPU を控えめに使い、貯めた CPU credit で一時的に全力を出す作りです。そして、何も指定しないと unlimited という設定で起動します。credit を使い切っても全力で走り続けられるかわりに、超えた分が 1 vCPU・1 時間あたり USD 0.04 で課金されます。暴走したプロセスが、そのまま請求になるわけです。この章の stack は standard にしてあります。credit が尽きたら遅くなるだけで、請求は増えません。

## 全体像

<!-- section: 23.architecture -->

```figure
caption: あなたも instance も自分から Systems Manager と S3 に接続し、外から instance に入る矢印は 1 本もない
type: sequence
actor you: Your machine | 自分の IAM identity
actor ssm: Systems Manager | ap-northeast-1
actor inst: EC2 instance | VPC AihNetwork
actor s3: S3 bucket | releases
step inst -> ssm: HTTPS 443 (SSM Agent)
step you -> ssm: send-command (HTTPS)
step you -> ssm: start-session (HTTPS)
step you -> s3: aws s3 cp
step inst -> s3: 自分の role で読む
```

```figure
caption: instance から Systems Manager と S3 への道は、private では VPC endpoint、public では internet gateway を通る
node inst: EC2 instance | VPC AihNetwork (11章), zone ap-northeast-1a
node vpce: VPC endpoints (11章の stack) | ssm, ssmmessages, ec2messages, S3 gateway
node igw: Internet gateway | instance の public IPv4 address
node ssm: Systems Manager
node s3: S3 bucket | releases
edge inst -> vpce: Private1 (既定)
edge inst -> igw: Public1 (-c placement=public)
edge vpce -> ssm
edge vpce -> s3
edge igw -> ssm
edge igw -> s3
```

```figure
caption: instance には、inbound のない security group、権限を 2 つに絞った role、IMDSv2 の設定が付く
node inst: EC2 instance AihEc2/instance | t4g.micro, Amazon Linux 2023 arm64
node sg: Security group | inbound なし, outbound tcp 443
node role: Instance profile の role
node imds: IMDSv2 | 必須, hop limit 1
node core: AmazonSSMManagedInstanceCore
node get: s3:GetObject | releases/*
edge inst -> sg
edge inst -> role
edge inst -> imds
edge role -> core
edge role -> get
```

```figure
caption: program と service は instance と一緒に消える root volume に、ノートは別の resource である data volume にある
node inst: EC2 instance AihEc2/instance
node root: Root volume | AMI から, instance と一緒に消える
node data: Data volume AihEc2/data | 8 GiB gp3, encrypted, 同じ zone
node current: /opt/notes/current | releases/<version>/server.mjs
node service: notes.service | systemd, user notes, 127.0.0.1:8787
node notes: /var/lib/notes/notes.json
edge inst -> root
edge inst -> data
edge root -> current
edge root -> service
edge data -> notes
```

外から instance に入ってくる矢印が 1 本もないことに気づきましたか。あなたが話しかける相手は Systems Manager で、instance は自分から Systems Manager に話しかけに行きます。ノート API も、instance の中の `127.0.0.1` でしか待ち受けません。
