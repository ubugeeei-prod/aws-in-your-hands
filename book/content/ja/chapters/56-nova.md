# 56 Nova: Amazon のモデルで文章、画像、動画、音声を扱う

Nova は 1 つのモデルの名前ではありません。Amazon が Bedrock で提供しているモデルの一族で、モデルごとに、受け取れる入力も、呼ぶ API も、東京から呼ぶときの ID も違います。しかも顔ぶれは入れ替わります。この章では、いま呼べるモデルを日付つきの一覧としてコードに持ち、その中から 1 つを選んで、ノートに添付した画像の説明文を作ります。

先に書いておくことがあります。この章の題には画像と動画が入っていますが、画像を生成する Nova Canvas と、動画を生成する Nova Reel は、2026-09-30 に Bedrock での提供が終わりました。音声で会話する最初の Nova Sonic も、2026-09-14 に終わっています。この章を書いている 2026-10-13 の時点で、Nova の一族に画像や動画を生成するモデルはありません。画像と動画は、モデルに読ませる入力としてだけ残っています。そのため、この章に生成の手順はありません。終了したモデルについては、既存のアカウントやコードで見かけたときに読めるように、何だったかを短く説明します。

モデルを呼ぶ仕組みそのもの、つまり Converse、inference profile、再試行は、[17章](/ja/chapters/17-ai.md)で扱いました。tool use やガードレールは [36章](/ja/chapters/36-bedrock.md)にあります。この章が足すのは、画像を入力として渡すこと、モデルを選び直すこと、そして、生成したものを 1 回だけ作って持ち主の場所に保存することです。

17章と同じく、手元ではモデルを呼びません。この章のテストと既定の開発サーバーは、手で書いた応答を再生するだけで、AWS には触れません。課金されるタスクは、出てくるたびにそう書きます。

前提は 17章と、画像のアップロードを作った [07章](/ja/chapters/07-uploads.md)です。コードは `examples/56-nova/` にあります。

## Nova の顔ぶれ

<!-- section: 56.family -->

次の表は、2026-10-13 に Bedrock のモデルカードで読んだ内容です。モデルカードは、ユーザーガイドにあるモデルごとのページで、入出力の種類、使える API、ID、呼べるリージョン、終了の目安が載っています。

| モデル | 入力から出力 | API | 東京リージョンからの呼び方 | コンテキストと最大出力 | 終了しない期限 |
| --- | --- | --- | --- | --- | --- |
| Nova 2 Lite | 文章、画像、動画から文章 | Converse、InvokeModel | `jp.` の profile（東京か大阪）か `global.` の profile。In-Region では呼べない | 100 万、6.4 万トークン | 2026-12-02 |
| Nova Lite | 文章、画像、動画から文章 | Converse、InvokeModel | In-Region（モデル ID のまま）か `apac.` の profile（6 リージョン） | 30 万、1 万トークン | 2025-12-05 |
| Nova Pro | 文章、画像、動画から文章 | Converse、InvokeModel | `apac.` の profile だけ | 30 万、1 万トークン | 2025-12-05 |
| Nova Micro | 文章から文章 | Converse、InvokeModel | ID を確認できていない | 12.8 万、1 万トークン | 2025-12-05 |
| Nova 2 Sonic | 音声、文章から音声、文章 | InvokeModelWithBidirectionalStream | In-Region | 100 万、6.4 万トークン | 2026-12-02 |
| Nova Multimodal Embeddings | 文章、画像、動画、音声から埋め込み | StartAsyncInvoke | 呼べない（us-east-1 と GovCloud だけ） | 記載なし | 2026-10-28 |

右端の列は、モデルカードの "EOL no sooner than" です。この日より前には終了しない、という約束の日付で、終了日ではありません。Nova Lite、Nova Pro、Nova Micro は、この日付をすでに過ぎています。状態は Active のままですが、終了の予告がいつ出てもおかしくない、という意味です。予告が出るとモデルは Legacy の状態になり、そこから終了までは少なくとも 6 か月あります。ただし Legacy に入ると、新しい利用者はそのモデルを使い始められません。

表の中で、はっきりしない点が 3 つあります。

Nova Micro は、モデルカードのリージョンの表では東京に Geo の印が付いています。ところが、同じページに載っている profile の ID は `us.` と `eu.` で始まるものだけで、東京から呼ぶための ID が見つかりません。この章は、ID を確認できないモデルを「呼べる」とは扱いません。

Nova Multimodal Embeddings は、モデルカードの API の欄では StartAsyncInvoke だけに印が付いています。一方で Nova 2 のガイドには、同じモデルを InvokeModel で同期的に呼ぶ例が載っています。どちらにしても東京からは呼べないので、この章では使いません。埋め込みと検索は [27章](/ja/chapters/27-search.md)が、東京で呼べるモデルで扱っています。

Nova 2 Lite は、ガイドによると PDF などの文書も読めます。モデルカードの入出力の欄には文書の項目がないので、表には入れていません。

もう 1 つ、ドキュメントどうしが揃っていないところがあります。Nova のドキュメントの入口のページは、Nova 2.0 の説明に Omni と Pro の名前を挙げています。AWS Price List には、Nova 2.0 Pro、Nova 2.0 Omni、Nova 2.5 Sonic の行があります。Nova の最初の版のユーザーガイドには、Nova Premier が載ったままです。しかし、どれにもモデルカードがなく、Nova 2 のガイドが挙げるモデルは、Nova 2 Lite、Nova 2 Sonic、Nova Multimodal Embeddings の 3 つだけです。この章は、モデルカードがあるものだけを、呼べるモデルとして扱います。料金表に行があることは、呼べることの証拠になりません。

## 終了したモデル

<!-- section: 56.retired -->

Bedrock のモデルは、Active、Legacy、End-of-Life の順に進みます。ライフサイクルのページには、終了日を過ぎたモデルの表があり、2026-10-13 の時点で Nova の 4 つの ID が載っています。

<<< @/examples/56-nova/src/catalog.ts{retired}

同じページは、これらのモデルは一覧のリージョンから取り除かれていて、リクエストは失敗する、と書いています。新しいモデルへの移行は自動では行われません。モデル ID を書き換えるのは、使っている側の仕事です。

古いコードや記事で見かけたときのために、それぞれが何だったかを書いておきます。

Nova Canvas は、文章や画像を受け取って画像を返すモデルでした。呼び方は同期の InvokeModel で、画像は応答の中に入って返ってきました。当時のガイドによると、生成したすべての画像に目に見えない透かしを入れ、Content Credentials による来歴の情報にも対応していました。

Nova Reel は、文章や画像から動画を作るモデルでした。動画の生成には時間がかかるので、呼び方は非同期の StartAsyncInvoke です。呼び出しはすぐに戻り、Bedrock があとで、指定した S3 の場所に呼び出しごとのフォルダを作って、`output.mp4` と `manifest.json`、状態を書いたファイルを置きました。ガイドには、6 秒の動画に約 90 秒かかるとあります。

Nova Sonic は、音声を受け取って音声で答えるモデルでした。後継の Nova 2 Sonic が、表にあるとおり東京でも呼べます。これは[しくみと実装](/ja/chapters/56-nova/build.md)の最後で触れます。

いま Bedrock で画像や動画を生成したい場合は、Nova 以外の提供元のモデルを、モデルカードの一覧から探すことになります。どれが東京から呼べるかは、この章では確かめていません。

StartAsyncInvoke という API そのものは残っています。Nova では Multimodal Embeddings が、長い動画や音声を区切って埋め込むときに使います。API リファレンスによると、呼び出しは重複を防ぐための `clientRequestToken` を受け取り、状態は `InProgress`、`Completed`、`Failed` のどれかになります。時間のかかる生成を非同期にして結果を S3 に置く、という形は Reel と一緒に消えたわけではありません。そのときに必ず出てくる 2 つの問いが、この章の後半の題材です。同じ仕事が 2 回終わったら出力はどうなるか。出力は誰の場所に置かれ、誰が読めるか。

この章のコードは、終了したモデルの ID を、最初のリクエストではなく起動の時点で断ります。たとえば環境変数に `amazon.nova-canvas-v1:0` を書くと、プロセスは「2026-09-30 に終了した」と表示して止まります。

## 全体像

<!-- section: 56.architecture -->

```figure
caption: 関数は、呼び出した人の接頭辞にあるアップロードをモデルに読ませ、説明文を同じ人の接頭辞に 1 つだけ保存する
node caller: Caller | 署名したリクエスト
node url: Lambda function URL | ap-northeast-1, AuthType: AWS_IAM
node fn: Lambda function | Node.js 24, arm64, 256 MB, タイムアウト 40 s
node bedrock: Amazon Bedrock Converse | inference profile jp.amazon.nova-2-lite-v1:0
node s3: S3 bucket | u/ アップロード, g/ 説明文, c/ claim
edge caller -> url: HTTPS、SigV4 で署名
edge url -> fn: 署名した人の ID
edge fn -> bedrock: 画像の S3 URI と質問
edge fn -> s3: 条件付きで書く
edge bedrock -> s3: 関数のロールで画像を読む
mark fn
```

作るのは、07章でアップロードした画像に、代替テキストを付ける API です。代替テキストは、画像を見られない読者のために画像の内容を文章にしたもので、HTML では `img` 要素の `alt` 属性に入れます。

入口は 17章と同じ function URL です。違うのは、モデルの答えを少しずつ返さないことと、S3 のバケットがあることです。説明文は 1 文か 2 文なので、できあがってからまとめて返します。そして、一度作った説明文は S3 に保存し、同じ画像について 2 回目に聞かれたら、モデルを呼ばずに保存したものを返します。画像が変わらなければ説明文も変える理由がないので、同じ答えに 2 度払うことはしません。

キューもテーブルも足していません。「誰かがいま作っている」という状態も、できあがった説明文も、S3 のオブジェクトとして持ちます。部品が少なくて済むのは、S3 が条件付きの書き込みを受け付けるからで、これは「しくみと実装」で説明します。

説明文を、アップロードの直後に自動で作りたい場合もあるはずです。そのときは、[08章](/ja/chapters/08-async.md)で作ったキューの先のワーカーから、この章の関数 `ensureDescription` を呼べば足ります。何度呼ばれても結果が同じになるように作ってあるので、キューが同じメッセージを 2 回届けても困りません。この章では、そこまではつないでいません。

一覧を今日の日付と照らして表示するタスクがあります。手元だけで動き、AWS は呼びません。

```bash
vp run nova:catalog
```

ただし、この一覧はドキュメントを読んで書いたもので、あなたのアカウントに聞いた結果ではありません。アカウントに聞くタスクも用意しました。

```bash
vp run nova:models
```

`nova:models` は、Bedrock の `ListFoundationModels` と `ListInferenceProfiles` を東京リージョンで呼び、Nova のモデルと profile を表示して、一覧と比べます。一覧にある経路がアカウントの側に見つからなければ、失敗で終わります。モデルは呼ばないので推論の料金はかかりませんが、AWS の認証情報が要ります。この章を書いている時点では実行していません。Nova Micro の ID のように、ドキュメントだけでは決められなかった点は、このタスクの出力で決めてください。
