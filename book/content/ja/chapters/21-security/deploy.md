# 21 Security: デプロイ

ここまでに作った既定のスタックを AWS にデプロイして確かめます。公開した URL に大量のリクエストが届いたときの歯止めも、このページで付けます。

## デプロイして確かめる

<!-- section: 21.deploy -->

既定のスタックだけなら、手順はこれまでの章と同じです。

```bash
vp run sec:infra:diff
vp run sec:infra:deploy
vp run sec:smoke
```

`sec:smoke` は、CloudFront の URL に対して、`/health`、トークンの発行、検証、署名を書き換えたトークンの拒否、POST の拒否を順に確かめます。トークンの発行は Secrets Manager を 1 回読むので、課金対象の API 呼び出しが 1 回発生します。

デプロイする前に知っておくべきことがあります。**既定のデプロイには、リクエストの数を止めるものが何もありません。** CloudFront はキャッシュしない設定なので、届いたリクエストはすべて Lambda まで行きます。`/token?sub=...` は認証なしで、誰にでも、どんな `sub` にでも署名します。このトークンを信用するものは、この章には何もありません。本物のサービスなら、発行の前に呼び出し元を認証します。URL を知られて大量のリクエストを送られたら、送られたぶんだけ請求になります。金額は[料金の「叩かれたら」](/ja/chapters/21-security/wrap.md)で計算します。

歯止めは 2 つ用意してあります。

1 つは web ACL で、IP アドレスごとに 5 分で 300 件までに制限します。この章でいちばん効く歯止めですが、月 USD 8.00 かかるので、既定では付けていません。付け方は[実装のつづきの「WAF を付けられる入口、付けられない入口」](/ja/chapters/21-security/more.md)にあります。

もう 1 つは、料金のかからない歯止めです。

```bash
vp run sec:infra:deploy -c reservedConcurrency=5
```

このオプションは、関数が同時に動く数を 5 つまでにします。超えたぶんは Lambda が断るので、Lambda の実行時間と、実行環境ごとに起きるシークレットの読み直しに天井ができます。ただし IP アドレスは見ないので、大量のリクエストが届いているあいだは、本物の利用者も一緒に断られます。CloudFront のリクエスト料金は、断られたぶんにもかかります。

新しいアカウントでこのデプロイが同時実行数のエラーで断られたら、Service Quotas でアカウントの上限を確かめてください。どの値から断られるのかは、確かめられていません。URL を誰かに渡す前に、2 つの歯止めのどちらかは付けておくことを勧めます。

関数 URL を直接呼べないことも確かめてください。Lambda のコンソールで関数の URL を調べて `curl` で呼ぶと、403 が返るはずです。

```bash
vp run sec:infra:drift
```

このスタックのリソースタイプは、どれも固定した版の cdkd が専用の実装を持っているものです。ドリフト検出で何がどこまで比べられるかは、実行していないので分かりません。なお、ローテーションはドリフトになりません。シークレットの値はテンプレートに無く、比べる対象にならないからです。
