# 63 Agent Sandbox: 手元で動かす

## 手元で確かめる

<!-- section: 63.local -->

この章で手元で動くのは、エージェントの周りにあるものだけです。エージェントは起動しません。モデルも GitHub も AWS も呼びません。認証情報は要らず、料金もかかりません。

テストは次のコマンドで動きます。

```bash
vp test run examples/63-agent-sandbox
```

テストが確かめていることを、守っているものの順に並べます。

- **不変条件。** 合成したスタックのタスクロールが、本番のテーブル、バケット、シークレット、デプロイ用のロール、ほかのタスク定義、自分のロググループのどれにも届かないこと。ロールを引き受けられるのが ECS のタスクだけで、渡せるのがランチャーだけであること
- **ランチャーの判断。** 一覧にないリポジトリ、上限を超えた時間と予算、同時実行数、1 日の予算で断ること。断った依頼のために GitHub とも ECS とも話さないこと。同じ依頼が 2 回届いても、ほぼ同時に届いても、タスクが 1 つしか起動しないこと。頼んだより広いトークンでは起動しないこと
- **タスクの手順。** トークンが渡るのはクローンとプッシュだけで、エージェントのプロセスにも、どのコマンドの引数にも入らないこと。プッシュ先が書き下した URL と作業用のブランチであること。エージェントが失敗したとき、期限に達したとき、変更が無いときに、何もプッシュしないこと
- **許可リスト。** 許可した名前を含むだけの名前、別のポート、IP アドレス、認証情報の入った URL を断ること。Claude Code の設定に入る宛先が、評価器の許す宛先と一致すること
- **リーパー。** 期限ちょうどで止めること。1 つが止まらなくても残りを止めること。タスクが無いときに CloudWatch を呼ばないこと

タスクの手順のテストは、コマンドを実行する関数を偽のものに差し替えています。Git も Claude Code も、実際には動いていません。確かめているのは、どのコマンドを、どの順序で、どの環境変数で呼ぶかです。コマンドが期待どおりに動くかどうかは、確かめていません。

ランチャーが 1 つの依頼をどう判断するかは、次のタスクで見られます。

```bash
vp run sandbox:plan
vp run sandbox:plan --repository acme/web
vp run sandbox:plan --running 2
```

1 つ目は、RunTask に渡す値、タスクの中で実行される `claude` のコマンド、設定ファイル、Network Firewall のルールの順に出力します。2 つ目と 3 つ目は、断る理由を出力します。時計は固定してあるので、何度実行しても同じ出力になります。

スタックの各ロールに何ができるかは、次のタスクで見られます。

```bash
vp run sandbox:policy
vp run sandbox:policy --exec
```

2 つ目は、ECS Exec を有効にした場合に、タスクロールに何が増えるかを示します。

synth は、タグの有無で中身が変わります。

```bash
vp run sandbox:infra:synth
vp run sandbox:infra:synth -c imageTag=a1 -c repositories=acme/notes
```

イメージに入る 2 つのファイルは、次のタスクで作れます。

```bash
vp run sandbox:bundle
```

手元で再現しないものは、エージェントに関わるすべてです。イメージのビルド（Docker のデーモンが Nix の shell にありません）、Fargate の中で Claude Code のサンドボックスが起動するかどうか、Bedrock への認証、GitHub とのやりとり、リーパーが実際のタスクを止めること。どれも、[デプロイ](/ja/chapters/63-agent-sandbox/deploy.md)の手順を通したときに初めて確かめられます。
