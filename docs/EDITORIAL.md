# 編集方針 / Editorial policy

日本語が正本です。技術内容を日本語で固め、意味と条件を変えずに英語にします。英語側で見つかった技術的な誤りは、必ず日本語側に戻します。

## 読者と約束

読者は TypeScript、HTTP、Git、Web アプリ開発には慣れているが、AWS のアカウント、IAM、ネットワーク、デプロイ、料金、運用は初めての開発者です。

読み終えた読者が説明できるようにすること:

- 何を作ったか、なぜその構成か
- コードがどこで動くか
- 何に料金がかかるか
- 手元で確かめられることと、実環境でしか確かめられないこと
- 本番で何を足すか

## 立ち位置

- Cloudflare と Vercel を尊重する。移行を前提にしない。AWS が常に安い・速い・優れているとは書かない。
- サービスの一覧を順に説明しない。読者が作りたい機能を中心に進める。
- AWS Amplify は使わない。CDK と SDK を中心に置く。
- 全機能を 1 つの巨大なサンプルに積み上げない。

## 固定している選択

変更には著者の判断が要ります。より慣れたツールがあるという理由で置き換えません。

| 対象 | 選択 |
| --- | --- |
| 本のサイトの生成 | Ox Content |
| 本のサイトのインフラ定義 | TypeScript と AWS CDK v2 |
| 本のサイトのリソース管理 | cdkd のみ。CloudFormation と交互に管理しない |
| 開発環境 | Nix（flake） |
| 依存の導入とタスク | Vite+（`vp`）。タスクの入口は `vp run` のみ |
| 既定のリージョン、通貨、月 | `ap-northeast-1`、USD、730 時間 |

cdkd の公式ドキュメントは cdkd を開発・テスト用途向けとし、本番には AWS CDK CLI を勧めています。この事実は本文に書き、執筆のたびに再確認します。それを理由に本のサイトの管理ツールを置き換えることはしません。

## 完成の定義

章を `complete` にしてよいのは、次がすべて揃ったときです。

1. 説明するすべての実装・設定・運用手順に、完全なソースがある。省略記号、未実装、架空の設定を含まない
2. 本文のコードは、実ファイルから `<<<` で取り込んでいる
3. すべての節に `<!-- section: ID -->` があり、`data/section-map.json` に対応がある
4. 取得、起動、検証、片付けの手順が `vp run` タスクとして実在する
5. 実行可能なローカル検証（`vp run check:all`）が通っている
6. 実行していない実環境の検証が、本文と `data/validation.json` に未検証として書かれている
7. 日英が同じ改訂番号で揃っている

書きかけの章は `planned` のままにします。薄い本文を完成扱いにしません。不完全なコードを動く例として配布しません。

## 2 つの状態を混ぜない

| 軸 | 値 | 記録する場所 |
| --- | --- | --- |
| 執筆 | `planned`、`draft`、`complete` | `data/chapters.json` の `writing` |
| 検証 | `unverified`、`local`、`aws` | `data/section-map.json` の `verification`、`data/validation.json` |

「書き終えた」は「動かして確かめた」を意味しません。ローカルで通ったことを、AWS で動く証拠として書きません。

## 章の型

手を動かす章は次を持ちます。当てはまらない項目は省き、水増ししません。

1. 成果と前提
2. 何がどこで動くかの小さな構成図（```text、日英共通）
3. この構成を選ぶ理由と、別の選択肢にする条件
4. 完全なソースと節ごとの対応表
5. ローカルでの起動、型検査、テスト。再現しないもの
6. diff、デプロイ、動作確認、drift 検出の手順と期待結果
7. 料金: 使っていないとき、使ったとき、消した後
8. 失敗例と調べ方
9. 本番に進めるなら変えること
10. 片付けと残るもの
11. 一次情報、確認日、検証範囲
12. 型で守ること、runtime validation、テストする invariant、部分障害の扱い

## 全章共通の設計基準

**type-safe。** TypeScript strict。型のつながりを CDK の設定、アプリ、API client、データまで通す。型の外から来る値（環境変数、HTTP、storage、queue、ツールの出力、AI の出力）は入口で schema と照合する。`any`、`@ts-ignore`、根拠のない `as` で境界を隠さない。型が IAM、サービスの上限、分散実行の正しさを保証するとは書かない。

**testable。** 時刻、乱数、外部の応答を注入できるようにする。unit、contract、CDK assertion、実環境の検証が、それぞれ何を確かめて何を確かめないかを書く。テストの件数や coverage を目的にしない。権限、公開設定、保持、cache の境界、認可、冪等性、置き換えなど、実害に結びつく条件を選ぶ。

**local DX。** clone から `nix develop` と `vp` で起動できる。変更のたびにデプロイを要求しない。認証情報も課金も要らない範囲を明示する。計測していない時間を書かない。

**drift。** ソース、template、state、実物を区別する。diff と drift を別の検査にする。「差が見つからなかった」と「すべて比べて一致した」を別の状態にする。

**分散。** 状態の持ち主、整合性とその範囲、同時更新、重複、再試行、部分障害を、関係する章で扱う。名前（global、serverless、durable、exactly-once）から保証を推測しない。invariant を 1 文で書き、壊そうとするテストを付ける。

## 料金

- 数値には、出典の URL、確認日、リージョン、プラン、通貨、課金単位を付ける
- 使用量の仮定を明示する。MAU だけで金額を出さない
- 入力と計算式は `data/pricing/` と `tools/src/pricing/` に置く。本文の金額は、そこから計算した値と一致させる
- 定価の小計と、無料枠・credits・割引の適用後の小計を分ける
- 確認できない料金と無料枠は「不明」とし、0 や推測で埋めない
- 予算の通知を、支出の上限として説明しない

## 一次情報

仕様、料金、安全性の主張は一次情報で確定します。公式ドキュメント、API リファレンス、CDK の API、公式の料金ページと Price List、固定した版のソースの順に、主張に合うものを使います。二次記事は調査の入口にはできますが、根拠にはしません。

参照したページと、それが支える具体的な主張を `data/sources.json` に記録します。執筆時に読み直していない出典は `checkedAt: null` とし、本文でも「未再確認」と表示します。

## 文体

- 用語は最初に使う箇所で平易に説明し、`data/glossary.json` に登録する
- API 名、CLI、ファイル名、resource ID、タスク名は翻訳しない
- 認定試験の暗記調、宣伝調、過度な強調を避ける
- 実行していないことを「〜のはず」「未検証」と書く。実行したかのように書かない
