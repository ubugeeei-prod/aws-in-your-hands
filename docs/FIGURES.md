# 図の書き方 / Writing figures

本文の図は、テキストの罫線で描かず、` ```figure ` のブロックに「何が何につながるか」だけを書く。
ビルド時に `book/theme/figure.ts` が配置を決めて SVG にする。線、書体、色はテーマが決めるので、本文では指定しない。

````md
```figure
caption: CloudFront が、読者の代わりに private な bucket を読む
node browser: Browser
node cf: CloudFront | distribution
node s3: S3 bucket | private, OAC
edge browser -> cf: HTTPS
edge cf -> s3: SigV4 で署名
group aws: AWS account = cf, s3
mark s3
```
````

## 行の種類

| 行 | 意味 |
| --- | --- |
| `caption: …` | 必須。図の下に出る説明で、スクリーンリーダーが読む文でもある。ページの言語で書く |
| `type: sequence` | 時系列の図にする。省略すると流れの図（`flow`） |
| `direction: right` | 流れの図を左から右へ並べる。省略すると上から下 |
| `node id: ラベル` | 箱を 1 つ。`ラベル \| 補足` と書くと、下に小さく補足が付く。区切りは前後に空白のある `\|` だけで、`GET\|POST` はそのままラベルになる |
| `actor id: ラベル` | 時系列の図の登場者。`node` と同じ書き方 |
| `edge a -> b: ラベル` | 矢印。ラベルは省略できる |
| `step a -> b: ラベル` | 時系列の図の 1 手。書いた順に上から下へ並ぶ。`step a -> a: …` は自分の中の処理 |
| `note id: 文` | 時系列の図で、その登場者の線の上に置く注記（状態の変化など） |
| `group id: ラベル = a, b` | 箱をまとめる枠（アカウント、VPC、stack など） |
| `mark id` | その章の主役に付けるオレンジの印。1 つの図に 1 つまで |
| `# …` | コメント |

矢印は 4 種類。

| 矢印 | 意味 |
| --- | --- |
| `->` | 呼び出し、データの流れ |
| `-->` | 破線。応答、非同期、あとから起きること |
| `-x` | 失敗、拒否（矢じりが × になる） |
| `--x` | 破線の失敗 |

## 配置の決まり方

- 箱の段（`direction: right` なら列）は矢印から決まる。矢印の先は、元より 1 つ先の段に置かれる
- 同じ段の中の並びは、`node` を書いた順
- 先に書いた `node` へ戻る矢印は、外側を回り込む線になる。段は動かさない
- 幅は文字数から見積もる。本文の幅は約 760px なので、横に長い鎖（5 個以上）は `direction: right` を使わず上から下に流す

## 書くときの決まり

- 図 1 つに言いたいことは 1 つ。箱が 9 個を超えたら 2 つの図に分ける
- 箱のラベルは名詞で短く。説明は本文か `caption` に書く
- 矢印のラベルは半角 28 文字以内を目安にする
- 色で意味を付けない。違いは、実線と破線、× の矢じり、枠、ラベルで表す
- ja と en で同じ構造にする。ラベルと caption だけを訳す
- コマンドの出力、ログ、ディレクトリの一覧、表は図ではない。` ```text ` のまま残す

## 確かめる

```bash
node book/theme/figure-cli.ts book/content/ja/chapters/03-spa.md
```

その Markdown の中の図をすべて読み、文法の誤りと、幅が本文に収まらない図を報告する。AWS にもネットワークにも触らない。
`vp run build:book` も、読めない図があれば、ページの名前と行を付けて失敗する。
